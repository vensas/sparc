sparc is a Claude Code plugin for spec-driven work with agents. A team of five roles takes each idea from a spark to a reviewed and tested change. The specs, the decisions and the documents agree with the code.

Install with the Claude Code CLI 
$ claude plugin marketplace add vensas/sparc
$ claude plugin install sparc@sparc

1.0

Agents write code fast. The rest falls behind.

Specs, decisions and documents get old after a few changes. An agent says "done" without proof and fills gaps with guesses. sparc puts a fixed process and two checks around the agent.

The painWhat sparc does
The documents do not agree with the code.Each fact has one home. Archive brings the specs, changelog, backlog, C4 diagrams and canvas in sync. A check without an LLM finds drift.
The agent says "done", but nothing proves it.The verifier runs lint, tests and the spec evidence. The agent cannot stop until they pass.
The agent reviews its own work with its own bias.A reviewer in a fresh context reads the diff. A QA engineer writes a test for each spec scenario.
Decisions get lost or change without a trace.Each major decision is an ADR in MADR format. The check uses git history to find a change to a decided ADR.
The agent fills gaps with guesses.A rule tells the agent to write only what it knows. Open points go to the architecture canvas.
Each project invents its own process.One plugin gives all projects the same loop, roles and document set, in known formats.
2.0

One loop for each change

Agents write code fast, but the specs and documents fall behind. In sparc, each feature or fix goes through the same steps. Running apply approves the change, so you do not type an approval.

  1. Propose

    /sparc:propose

    Proposal, specs, design, tasks and mockups.

    Product owner, architect, UX designer

  2. Apply

    /sparc:apply

    Tests first, then the code for each task.

    Software engineer

  3. Review

    Fresh context

    A reviewer without the session history reads the diff.

    Software engineer

  4. QA

    qa.md

    An automated test for each spec scenario.

    QA engineer

  5. Verify

    Stop hook

    Lint, tests and evidence must pass before the agent can stop.

    Verifier, no LLM

  6. Archive

    /sparc:archive

    Specs, changelog, backlog, C4 and canvas in sync.

    Product owner, architect

  7. Release

    /sparc:release

    Version, changelog and tag with Conventional Commits.

    You

sparc adds the roles, the document set and two checks on top of OpenSpec.

3.0

Five roles, one owner for each document

A role is a rule file that a skill follows. Each role owns its documents, so each fact has one home.

RoleDoesOwns
Product ownerWrites testable requirements. Accepts the change from the QA report.docs/backlog.md, proposal, specs
ArchitectDesigns the simplest structure. Writes decisions with their options.README, C4, canvas, ADRs, design, tasks
UX designerValidates an interface with static mockups first.docs/mockups/
Software engineerImplements test first. Reviews the change in a fresh context.Code and tests
QA engineerProves each spec scenario with an automated test.qa.md

6.0

Questions

Does sparc work with other coding agents?

No. sparc is a Claude Code plugin. It uses the skills and hooks of Claude Code, in the CLI and in Claude Desktop.

Do I need OpenSpec?

Yes. sparc adds its rules to OpenSpec through openspec/config.yaml and calls the OpenSpec CLI. Install it with npm install -g @fission-ai/openspec.

Can I use sparc in an existing code base?

Yes. Run /sparc:init in the folder of the project. The architect documents what it finds in the code.

Must a small fix go through the full loop?

Yes. Each change of behavior goes through propose, apply and archive. This is the cost of specs and documents that stay correct.

What does sparc cost?

sparc is free under the MIT license. It uses more tokens: the fresh-context review starts one more agent for each change. One measured change used 60,560 tokens and 36 seconds for the review.

Does sparc work with pull requests?

Yes. Choose the workflow trunk or pull-request in openspec/config.yaml. In the pull request workflow, the review or the merge is the approval.

Can I add the rules of my team?

Yes. Write each rule in its home: a rule for each change in AGENTS.md, a quality requirement in the canvas, a testable behavior as a spec scenario, and a check as a Verify command.

Why is the English so plain?

All English text in sparc follows ASD-STE100 Simplified Technical English on purpose. Short sentences and one word for one meaning give agents and readers one clear meaning.

How do I update sparc?

Run claude plugin marketplace update sparc and claude plugin update sparc@sparc. Then run /sparc:update in each project.

7.0

Install and start a project

Prerequisites: Claude Code, Node.js, git and OpenSpec.

  1. Install OpenSpec.

    npm install -g @fission-ai/openspec

  2. Add the marketplace and install sparc. In Claude Desktop, use Plugins, then Add from repo.

    claude plugin marketplace add vensas/sparc
claude plugin install sparc@sparc

  3. Open the folder of your project and tell the idea one time.

    /sparc:init <project idea>

  4. Propose each feature or fix. Then apply and archive it.

    /sparc:propose <feature>
